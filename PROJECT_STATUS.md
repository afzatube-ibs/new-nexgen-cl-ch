A **self-review caught and fixed a second, more severe platform-wide defect** introduced while building this module's eight cross-domain listeners: none of them originally caught their own exceptions, so a missing/misconfigured notification template (a routine, expected condition on a fresh installation) propagated straight back through the synchronous event bus into the *triggering* module's own transaction — surfacing as 24 unrelated test failures across Orders, Payments, Checkout, Customers, and Returns, since `OrderPlaced`/`PaymentCaptured`/`PaymentRefunded`/etc. are published from inside those modules' own core Actions. Fixed by wrapping every listener's notification-queuing call in a try/catch that reports and swallows the failure — a notification failure must never be able to break the workflow that triggered it, per this module's own "MUST NOT contain business logic from Orders, Payments, Shipping, Fulfillment, Returns, Customers... never the owner of business workflows" rule. A related reliability gap (a provider's own HTTP call throwing a raw connection-level exception, rather than returning a failed result, could leave a Notification stuck in `sending` forever) was found and fixed the same way.

A genuine, non-obvious **testing-infrastructure finding**: InnoDB/MariaDB FULLTEXT indexes only consider committed data — a row inserted inside a test's own open transaction (this project's standard `RefreshDatabase` isolation, used by every prior module's test suite) is invisible to a real `MATCH ... AGAINST` query, which silently returned zero results for every FULLTEXT-dependent test until diagnosed. Fixed by adopting Laravel's `DatabaseTruncation` trait (real commits, truncated afterward) for the handful of tests that specifically exercise FULLTEXT relevance ranking — with an explicit `afterEach` cleanup added after discovering `DatabaseTruncation` only truncates *before* each test in its own file, never after, which would otherwise have leaked committed rows into every `RefreshDatabase`-isolated test class running later in the same process for the rest of the suite, not just this module's own tests.
